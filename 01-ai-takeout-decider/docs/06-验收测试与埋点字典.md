# 验收测试与埋点字典

> 测试对象：V0.9 响应式交互原型  
> 测试角色：目标用户、产品经理、设计师、前端/算法工程师  
> 测试数据：30 道模拟菜单，不包含真实订单与用户隐私数据

## 1. 测试策略

测试按风险而不是页面数量组织：

1. **安全与正确性**：硬约束不得被推荐逻辑覆盖。
2. **核心价值**：能否生成三个可区分、可理解、可采用的结果。
3. **控制与恢复**：锁定、替换、无结果和错误状态是否可恢复。
4. **学习闭环**：反馈是否改变偏好且不推断敏感属性。
5. **度量可信度**：事件能否支撑有效决策率和漏斗计算。

## 2. P0 验收场景

### TS-01 正常完成一次三选一决策

**测试目标**：验证从设置条件到模拟下单的核心路径。  
**初始条件**：清空本地状态；位置杭州·滨江；菜单数据可用。  
**用户角色**：时间有限的职场新人。

**步骤与预期**

1. 进入首页：显示当餐时段、默认“均衡一点”、预算 32 元和 40 分钟。
2. 选择“赶时间”：模式高亮，速度权重同步提高，动态问题更新。
3. 点击推荐：出现加载状态，随后展示不重复的三份推荐。
4. 查看任一推荐：可见价格、ETA、营养区间、理由、取舍、置信度。
5. 点击“就这份”：出现明确标记为模拟的下单弹窗。
6. 选择平台：记录 `order_handoff`，不创建真实订单，并进入反馈流程。

**最终结果**：整个任务无死路，用户能完成一次可记录的决策。

### TS-02 预算边界必须严格生效

**测试目标**：验证价格是硬约束。  
**初始条件**：预算设为 20 元，其他条件宽松。  
**用户角色**：校园预算型用户。

**步骤与预期**

1. 调整预算为 20 元：页面显示 `¥20`。
2. 请求推荐：所有结果价格≤20 元。
3. 多次换一批和替换：新结果仍全部≤20 元。
4. 锁定一个结果后换一批：锁定项保留且仍满足预算。

**最终结果**：预算违规结果为 0；商业推荐也不得绕过预算。

### TS-03 送达时限必须严格生效

**测试目标**：验证 ETA 是硬约束。  
**初始条件**：最晚送达设为 25 分钟，预算 60 元。  
**用户角色**：赶会议的职场用户。

**步骤与预期**

1. 选择 25 分钟并请求推荐。
2. 检查三份结果和后续替换结果。
3. 所有结果的模拟配送时间均≤25 分钟。

**最终结果**：系统不得为了口味或健康得分展示超时结果。

### TS-04 多个排除项同时生效

**测试目标**：验证排除项交集过滤。  
**初始条件**：选择“辣”“海鲜”“乳制品”。  
**用户角色**：有明确饮食偏好的用户。

**步骤与预期**

1. 选中三个排除项：每个状态清晰可见。
2. 请求推荐并查看全部结果。
3. 结果数据的 `flags` 不得包含任一已选项。
4. 页面持续显示“不作为过敏原安全承诺”的说明。

**最终结果**：筛选准确，但产品不将偏好过滤描述为医疗安全保证。

### TS-05 无结果时不自动放宽条件

**测试目标**：验证失败状态透明且可恢复。  
**初始条件**：使用测试数据制造无候选组合。  
**用户角色**：设置严格条件的用户。

**步骤与预期**

1. 提交无法满足的条件。
2. 系统显示没有合适选项，而不是推荐违规菜品。
3. 点击“调整条件”返回设置区域。
4. 放宽一个条件后可重新生成结果。

**最终结果**：失败可解释、可恢复，不隐藏约束冲突。

### TS-06 三份结果差异化且解释完整

**测试目标**：验证主推荐、时间更稳和营养更优三个位置。  
**初始条件**：默认均衡模式。  
**用户角色**：健康平衡型用户。

**步骤与预期**

1. 请求推荐后记录三个菜品 ID：ID 不重复。
2. 检查标签：分别为“最合你意”“时间更稳”“营养更优”。
3. 展开四项匹配度：分数范围 0–100。
4. 检查理由与取舍：均有内容且不包含未提供的食材或功效。
5. 检查营养：使用区间，且展示置信度。

**最终结果**：用户能理解三份为何不同，而不是看到三个相似最高分。

### TS-07 锁定、单项替换和批量刷新

**测试目标**：验证用户控制感和状态一致性。  
**初始条件**：已展示三份推荐。  
**用户角色**：希望继续比较的用户。

**步骤与预期**

1. 锁定第一份：出现“已锁定”。
2. 点击换一批：第一份保持，其他项改变且不重复。
3. 对第二份点击单项替换：只改变该位置。
4. 将三份全部锁定后点击换一批：不改变结果，并提示先取消锁定。
5. 取消一个锁定后再次刷新：仅未锁定位置更新。

**最终结果**：锁定状态不丢失，替换不产生重复或意外重置。

### TS-08 有效决策率口径正确

**测试目标**：验证 60 秒和硬约束共同决定有效会话。  
**初始条件**：可读取事件导出数据。  
**用户角色**：产品分析人员。

**步骤与预期**

1. 60 秒内选择合规结果并跳转：`effective=true`。
2. 超过 60 秒选择合规结果：记录跳转，但 `effective=false`。
3. 使用测试桩选择违规结果：必须被前置拦截；若进入跳转则为严重缺陷。
4. 同一会话多次点击：北极星按会话去重。

**最终结果**：点击量不能被误计为多次有效决策。

### TS-09 餐后反馈更新轻量偏好

**测试目标**：验证反馈闭环和边界。  
**初始条件**：已模拟下单一道菜。  
**用户角色**：完成用餐的用户。

**步骤与预期**

1. 味道、分量、推荐准确度分别选择 1–5 分。
2. 味道≥4：对应菜系偏好上升但不超过上限。
3. 味道≤2：对应菜系偏好下降并记录不喜欢的菜品。
4. 再次推荐：只产生轻量排序修正，硬约束不受影响。
5. 打开偏好档案：可看到“偏爱/少推”标签，不出现疾病或身份推断。

**最终结果**：反馈可观察地影响后续排序，且不越过隐私边界。

### TS-10 验证数据可导出

**测试目标**：验证原型研究数据的可追踪性。  
**初始条件**：至少完成一次推荐、替换、跳转和反馈。  
**用户角色**：产品研究人员。

**步骤与预期**

1. 打开偏好档案并点击导出。
2. 下载 JSON 文件，包含 `schemaVersion`、`exportedAt`、`profile` 和 `events`。
3. 每个事件包含事件名、时间、会话 ID 和属性。
4. 文件不包含真实姓名、精确地址或支付数据。

**最终结果**：导出可用于验证分析且符合最小化采集原则。

## 3. 非功能与边界场景

| ID | 场景 | 预期结果 |
|---|---|---|
| TS-11 | 320px 手机宽度 | 文本、按钮和推荐卡无横向溢出或重叠 |
| TS-12 | 桌面宽度 | 设置与结果并列，阅读顺序和键盘顺序合理 |
| TS-13 | 仅键盘操作 | 所有输入、展开、弹窗、关闭和主要操作可完成 |
| TS-14 | 图片加载失败 | 显示菜系降级色块，不影响文字和操作 |
| TS-15 | 本地存储不可用 | 核心推荐仍可使用；个性化和导出明确降级 |
| TS-16 | 重复快速提交 | 不出现重复卡片、弹窗叠加或事件异常膨胀 |
| TS-17 | 数据置信度低 | 不将该项放在“营养更优”，且不显示虚假精确值 |
| TS-18 | 系统减少动画设置 | 不依赖循环动画传达必要状态 |

## 4. 缺陷优先级

| 等级 | 定义 | 示例 | 处理要求 |
|---|---|---|---|
| P0 阻断 | 违反安全或核心承诺 | 超预算、排除项违规、创建真实订单 | 立即停止测试与发布 |
| P1 严重 | 主流程无法完成或指标失真 | 无法生成推荐、锁定丢失、有效决策重复计数 | 当前迭代修复 |
| P2 一般 | 有替代路径但明显影响体验 | 图片失败无降级、说明难理解 | 下一迭代修复 |
| P3 轻微 | 不影响任务完成 | 次要间距或文案问题 | 记录并排期 |

## 5. 通用事件字段

每个事件都应包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `event_id` | string | 事件唯一 ID |
| `event_name` | string | 事件名称 |
| `occurred_at` | ISO datetime | 客户端发生时间 |
| `session_id` | string | 一次决策会话 ID |
| `anonymous_user_id` | string | 匿名用户 ID，原型可仅保存在本地 |
| `prototype_version` | string | 原型或规则版本 |
| `experiment_variant` | string/null | 实验分组，无实验时为空 |

不得默认记录真实姓名、手机号、精确地址、支付信息和自由文本中的敏感内容。

## 6. 事件字典

| 事件名 | 触发时机 | 关键属性 | 支撑指标 |
|---|---|---|---|
| `session_viewed` | 决策页首次可用 | `menu_item_count` | 访问、设置完成率分母 |
| `mode_selected` | 选择当餐模式 | `mode` | 模式分布、分群 |
| `budget_changed` | 确认预算调整 | `budget` | 预算分布、输入摩擦 |
| `deadline_changed` | 选择最晚送达 | `deadline` | 时间约束分布 |
| `exclusions_changed` | 排除项变化 | `exclusions` | 条件复杂度 |
| `adaptive_answered` | 回答动态问题 | `mode`,`factor` | 问题完成率、偏好分布 |
| `weight_changed` | 高级权重调整 | `factor`,`value` | 默认权重适用性 |
| `location_changed` | 切换用餐区域 | `location` | 区域分布、数据覆盖分析 |
| `recommendation_requested` | 提交当前条件 | `constraints`,`weights`,`location` | 设置完成、请求量 |
| `recommendations_shown` | 结果完成展示 | `eligible_count`,`item_ids`,`latency_ms` | 漏斗、候选可用、P95 |
| `recommendation_locked` | 锁定某项 | `item_id`,`position` | 控制感、候选保留 |
| `recommendation_unlocked` | 取消锁定 | `item_id` | 锁定反悔 |
| `recommendation_replaced` | 单项替换 | `from_item_id`,`to_item_id`,`position` | 平均替换、推荐质量 |
| `recommendation_batch_refreshed` | 换一批 | `locked_ids`,`refresh_index` | 继续探索比例 |
| `order_dialog_opened` | 打开模拟下单 | `item_id`,`position`,`elapsed_ms` | 选择率 |
| `order_handoff` | 选择下单平台 | `item_id`,`platform`,`elapsed_ms`,`effective` | 有效决策率、跳转完成 |
| `meal_feedback_submitted` | 提交餐后反馈 | `item_id`,`cuisine`,`ratings` | 低分率、反馈率、学习 |
| `profile_opened` | 打开偏好档案 | 无 | 偏好透明度使用率 |
| `validation_data_exported` | 导出本地数据 | `schema_version` | 研究操作审计 |

## 7. 指标到事件映射

| 指标 | 分子事件 | 分母事件 | 关键过滤 |
|---|---|---|---|
| 有效决策率 | `order_handoff` | `recommendations_shown` | `effective=true`，按会话去重 |
| 首次设置完成率 | `recommendation_requested` | `session_viewed` | 每个匿名用户首次会话 |
| 下单跳转完成率 | `order_handoff` | `order_dialog_opened` | 按会话和 item 去重 |
| 平均替换次数 | `recommendation_replaced` | `recommendations_shown` | 排除 QA 和自动事件 |
| 餐后反馈率 | `meal_feedback_submitted` | 可归因订单 | 真实 MVP 才可计算 |

## 8. 测试记录要求

执行每个测试时记录测试人、日期、版本、设备、初始数据、实际结果、证据截图、缺陷 ID 和结论。失败用例必须在修复后重新执行，不以“开发解释了原因”代替复测。
