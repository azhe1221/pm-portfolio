# 面试讲解与 90 秒演示脚本

## 1. 三分钟版本（先讲结论，再讲取舍）

### 0:00–0:25 问题

“自然语言选股最大的问题不是‘听不懂’，而是‘听懂了但不可检查’。比如‘估值合理’，可以是 PE 低、PB 低、行业分位低，也可以是 PEG 低。如果我直接给结果，用户没法判断我到底按什么口径选的，也没法改。”

### 0:25–0:55 方案

“所以我做了一个**条件编译器**：把一句话拆成条件卡，每张卡包含因子、运算符、阈值、单位、硬性/加分、数据来源和口径假设。用户可以逐条改；改完由确定性引擎跑全市场，AI 不碰计算。”

“AI / 规则 / 数据 / 人的边界是：AI 负责听懂和解释，规则负责求值和排序，数据层负责字段和时点，人负责确认口径和最终判断。”

### 0:55–1:35 演示

“输入‘经营改善、估值合理、走势相对稳定’，它会拆成 8 个条件、3 条口径假设。‘经营改善’默认是营收同比≥10%、归母净利同比≥10%、报告期 ROE≥10%；‘估值合理’是 PE≤30 且行业 PE 分位≤50%；‘走势稳定’是波动率≤30%、最大回撤≥-15%、站上 MA60。”

“这里 8 个都是硬条件，结果只有 4 只。这不是 bug，是产品要暴露的取舍：条件越硬，结果越少。我把‘走势稳定’切成加分项，结果会变多；条件影响页可以拖动 PE 阈值，直接看到‘+N/-N 只’，新进/移出是谁。”

### 1:35–2:15 解释与数据

“点开任意一只，能看到每个条件的实际值、通过/未通过/数据不足、原因、数据源、财务报告期。比如这只 2026 三季报，ROE 15.33%，PE 11.52，行业分位 13.6%。”

“数据层对负 PE 的处理是：置空 + 标记，不当作便宜；财务缺失不当作 0；增速超过 300% 标记异常；行业样本不足 8 只，分位置空。这些都在数据质量页，能回到字段和时点。”

### 2:15–2:45 取舍

“我没有做回测和监控，也没有硬说接了扶摇/iFinD。当前用的是公开接口的真实快照，盘中 10:12，页面明确标注；数据源可替换。LLM 也是可选：本地解析器默认可用，配了 Key 才走 LLM，失败回退。”

“如果继续做，我会先接扶摇/iFinD，再加‘定时刷新 + 新进/移出’监控，最后才考虑回测——因为这类产品先把口径和证据做对，比先给收益曲线更重要。”

### 2:45–3:00 收尾

“一句话总结：这不是一个‘AI 告诉你买什么’的产品，而是一个‘AI 帮你把选股想法变成可检查条件，并告诉你为什么’的工作台。”

## 3. 高频追问与答法

### Q1：为什么不让 LLM 直接选股？

“LLM 适合语义，不适合对 5,215 只做确定性过滤。更重要的是可追溯：每个数字要能回到字段和时点。LLM 直接给结果，错了很难定位。我的边界是 LLM 只做解析/解释，规则做计算。”

### Q2：“估值合理”为什么是 PE≤30 + 行业分位≤50？

“这是默认的‘均衡’口径，不是唯一正确答案。绝对值防行业整体高估，行业分位防跨行业拿银行 PE 买科技。用户可以在严格/均衡/宽松之间切，也可以逐条改。产品把假设摆出来，而不是假装 AI 懂。”

### Q3：为什么只有 4 只？是不是太严？

“是 8 个硬条件的自然结果。产品没有偷偷放宽来让结果好看，而是提供两个出口：把某条改成加分项，或拖敏感性滑杆看放宽的代价。面试里我更愿意展示这个取舍，而不是用 200 只结果掩盖口径。”

### Q4：负 PE 怎么处理？为什么不直接排除？

“负 PE 是亏损，不是便宜。直接排除会丢掉‘亏损但可能反转’的股票；当作低估值又错。我的处理是置空 + 标记 `NEGATIVE_PE`，估值条件判为数据不足，并在详情里说明。用户可以选择不跑估值条件。”

### Q5：数据源为什么不是扶摇/iFinD？

“题目优先建议扶摇/iFinD，但它们需要 API Key；本次构建没有可用凭据。我用公开接口完成了真实快照，并把数据获取隔离成三个函数，替换数据源不影响前端和引擎。这是取舍，我在 README 和数据说明里明确写了，没有伪装成已接入。”

### Q6：为什么不做回测/监控？

“24 小时里，回测很容易做成‘曲线好看但口径不可信’。我优先把条件、证据、缺失和敏感性做对；回测/监控是下一步，产品说明里列为未做。题目要求‘比较、保存、回测或监控’四选一，我做了比较 + 保存 + 导出，没有冒充四件都做了。”

### Q7：AI 在哪里？没有 Key 不就没 AI 了？

“默认是本地规则解析器，保证离线可用；配置 Key 后走 LLM，前端再做白名单/类型/区间二次校验，失败回退。AI 是增强，不是单点故障。对面试产品来说，能演示、能回退比‘必须联网’更重要。”

### Q8：这个产品的成功指标是什么？

“条件确认率、条件修改率、解释打开率、0 结果率、数据缺失提示率、任务完成时间。不是入选股票的收益——因为产品不做预测，用未来收益证明产品价值是错的。”

### Q9：如果给你两周，你先做什么？

“第一周接扶摇/iFinD + 定时刷新 + 新进/移出监控；第二周做 5–8 位真实用户的可用性测试，重点看‘用户是否真的会改条件’和‘0 结果时会不会放弃’。回测放在口径和监控稳定之后。”

### Q10：你最大的取舍是什么？

“放弃‘大而全’：不做预测、不做回测、不接四个市场、不硬编股息率。把范围收敛到‘一句话 → 可检查条件 → 逐只解释’，保证这条链路真实可运行、可追溯。”

## 4. 现场演示注意事项

- 先开好 `node server/server.js`，浏览器提前打开 `http://127.0.0.1:8080/?q=经营改善、估值合理、走势相对稳定`，避免现场等 4.4MB 数据加载。
- 不要一上来讲技术栈；先讲“用户的问题是什么、产品怎么解决”。
- 结果只有 4 只时，主动讲“这是 8 个硬条件的取舍”，不要等面试官问。
- 被问数据源，主动承认不是扶摇/iFinD，讲可替换适配层和取舍；不要编。
- 被问 AI，明确“本地解析器默认、LLM 可选、规则执行、数字可回溯”。
- 结尾一定带合规：“不构成投资建议，不预测涨跌”。

## 5. 不要说的话

- “这个策略能赚钱 / 收益很高 / 肯定涨。”
- “我接了扶摇/iFinD”（如果没有）。
- “我做了回测/监控”（如果没有）。
- “AI 全自动选股，人不用管。”
- “这个结果就是正确答案。”
