# AI 使用与验证记录

> 说明：本记录按**实际构建过程**写，不虚构“候选人已经逐条复核”。AI 负责初稿与重复劳动，构建过程中已经发现并修正了一批错误；提交前候选人仍需按文末清单亲自走一遍。

## 1. 使用了哪些 AI / 工具

| 工具 | 用途 |
|---|---|
| DeepSeek Harness AI Coding 助手 | 需求拆解、数据管道、解析器/引擎、前端、测试、文档初稿 |
| Python 3（标准库 urllib/json/ThreadPoolExecutor） | 公开数据抓取、快照构建、数据校验 |
| Node.js 24 | 本地静态服务、命令行测试、接口冒烟 |
| Chrome Headless | 页面截图验收（首页、结果页、详情、条件影响） |

没有使用真实 LLM API Key。产品里的 LLM 解析代理只用 `LLM_MOCK=1` 做了接口、结构校验与回退测试。

## 2. AI 参与了哪些环节

| 环节 | AI 参与 | 人工/确定性校验 |
|---|---|---|
| 数据字段与因子口径 | 提出 PE/PB/ROE/增速/波动/回撤等映射 | 用真实快照和关键股票交叉检查；负 PE、缺失、过期单独处理 |
| 自然语言解析器 | 生成同义词、预设、数值/单位/运算符解析代码 | 10 条测试用例回归；对“经营改善/估值合理/走势稳定”逐条确认假设 |
| 筛选引擎 | 生成条件求值、硬/软过滤、分位评分、敏感性代码 | 单元测试覆盖负 PE、财务缺失、冲突、软条件、敏感性 |
| 前端 | 生成布局、条件卡、结果表、详情抽屉、对比/保存/导出 | 浏览器截图验收；修布局与交互问题 |
| 文档 | 生成 README、产品说明、数据说明、测试说明初稿 | 与真实文件、真实数字逐项对齐；不写未实现的“监控/回测” |
| 可选 LLM | 生成系统 Prompt 与 JSON 结构 | 因子白名单、运算符、类型、区间二次校验；失败回退本地 |

## 3. AI 生成后，发现并修正了哪些问题

以下问题是我在构建/验收过程中发现并要求修正的（AI 生成初稿，我逐项确认）。保留下来是为了说明“AI 初稿不能直接信”。

| 问题 | 表现 | 修正 |
|---|---|---|
| 重复条件 | “毛利率高于30%”同时触发数值条件和“高毛利”特殊词，出现 `gross_margin > 30` 与 `>= 30` 两条 | 特殊词先检查同因子是否已有条件 |
| 行业匹配过宽 | “半导体”被扩成“半导体 + 元件 + 电子化学品” | 先精确匹配行业名，匹配不到才用别名扩展 |
| 只有排除项被误报 | “不要ST，排除停牌，只要主板”没有条件，却被列进 `unparsed` | 增加 `optionsTouched`，选项变更也算识别成功 |
| 阈值展示带加号 | 条件卡显示“≥ +10.00%”，像涨幅而不是阈值 | 条件阈值格式化关闭 signed |
| 负 PE 被当便宜 | 初版只判断 `pe_ttm <= 30`，负 PE 可能通过 | 负 PE 置空 + `NEGATIVE_PE`，条件返回 `missing` |
| 浏览器缓存旧 JS | 改了 app.js 但截图仍是旧页面 | 静态资源加版本参数；服务端 JS/CSS/JSON 改 `no-cache` |
| 保存按钮双触发 | “保存当前策略”同时绑定了直接监听和事件委托，可能弹两次 prompt | 只保留事件委托 |
| 条件卡模式按钮换行 | “硬性/加分”在窄卡片里竖排 | 固定 `flex: 0 0 auto`、`white-space: nowrap`，左侧文本可换行 |
| 极端 PE 未提示 | 有股票 PE 116,696x，页面直接显示 | 前端增加 `PE_EXTREME` 标记（盈利接近 0，估值失真） |
| 刷新覆盖风险 | 18:xx 全量刷新时日 K 被限流，若继续会写入大量缺失 | 终止刷新，保留 10:12 完整快照；页面明确标注盘中时点 |

## 4. 可选 LLM 的设计与验证

### 4.1 Prompt 约束

- 只允许使用固定因子 key（`pe_ttm`、`roe`、`vol_60d` 等 26 个）。
- 模糊词必须展开为代理条件，口径写进 `assumptions`。
- 亏损股 PE 不能当低估值；缺失不能补 0。
- 识别不了的放 `unparsed`，有歧义放 `ambiguities`。
- 不输出买卖建议、目标价、收益承诺。

### 4.2 二次校验

`normalizeLLMResult()` 在客户端再做一次：

- 因子必须在 `FACTORS` 白名单内；
- 运算符必须是允许集合；
- 数值必须有限；布尔必须是 boolean；
- `between` 必须有第二个阈值；
- 未知/非法项丢弃并写入 `unparsed`，不直接执行；
- LLM 请求失败、返回空条件、JSON 解析失败时，回退本地解析器。

### 4.3 验证记录

| 场景 | 结果 |
|---|---|
| `GET /api/health`（无 Key） | 200，`llm.configured=false` |
| `POST /api/parse`（无 Key） | 501 `LLM_NOT_CONFIGURED`，前端回退本地 |
| `POST /api/parse`（`LLM_MOCK=1`） | 200，返回 5 个条件、options、assumptions |
| 编码路径穿越 `/..%2F..%2FWindows%2Fwin.ini` | 403 `FORBIDDEN` |
| 页面 `?q=经营改善、估值合理、走势相对稳定` | 8 个条件、4 只入选，截图验收 |
| 详情 `?q=...&detail=002128` | 逐条件解释、数据口径、风险标记正常 |
| 条件影响 `?q=...&tab=impact` | 8 个滑杆，显示当前 4 只 |

## 6. AI 没有做什么

- 没有编造行情、财务、K 线数字；所有数字来自 `data/snapshot.json`。
- 没有生成“用户反馈”“业务增长”“收益提升”等未发生的结论。
- 没有让 LLM 直接决定筛选结果；LLM 只做意图解析，且可回退。
- 没有把“监控/回测/公告原文”写成已实现；README 和产品说明都列为未做。
- 没有把东方财富公开接口伪装成扶摇/iFinD；数据说明明确披露。

## 7. 候选人提交前复核清单

请务必亲自做一遍，确认你讲得出来：

1. `node server/server.js`，打开首页，点“经营改善 + 估值合理 + 走势稳定”示例，确认 4 只结果。
2. 点第一只股票，能解释：它为什么入选？每个条件的实际值是多少？财务报告期是哪天？
3. 到“排除”页，随便点一只，能解释：它是条件不符，还是数据缺失？两者区别是什么？
4. 把“走势稳定”改成“加分项”，看结果数量变化；能解释硬条件 vs 加分项的设计取舍。
5. 到“条件影响”，拖动 PE 阈值，能解释“条件变化会带来什么影响”不是“收益回测”。
6. 到“数据质量”，能说出快照时点、负 PE 数量、K 线覆盖率、财务报告期分布。
7. 点“自检”，确认 10/10 通过；能解释测试覆盖了什么、没覆盖什么。
8. 检查 README 中的数据源披露：为什么用东方财富、为什么不是扶摇/iFinD；如果面试官追问，能诚实回答。
9. 如果部署到公网，把 README/提交邮件里的 `http://127.0.0.1:8080` 换成真实 URL；确认 `data/snapshot.json` 一起上传。
10. 检查仓库没有 API Key、个人信息、临时截图/浏览器 profile。
