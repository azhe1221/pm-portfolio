## 2. 数据源

当前版本使用东方财富公开接口。它们是真实、可回溯的公开数据，但不是题目优先建议的扶摇/iFinD。

| 数据 | 接口 | 主要字段 | 时点 |
|---|---|---|---|
| 行情快照 | `push2.eastmoney.com/api/qt/clist/get` | f2 最新价、f3 涨跌幅、f8 换手率、f10 量比、f20 总市值、f21 流通市值、f23 PB、f115 PE(TTM)、f9 动态 PE、f24 60日涨跌幅、f25 年初至今、f100 行业 | 2026-10-26 10:12 |
| 财务指标 | `datacenter-web.eastmoney.com/api/data/v1/get?reportName=RPT_F10_FINANCE_MAINFINADATA` | REPORT_DATE、NOTICE_DATE、TOTALOPERATEREVE、PARENTNETPROFIT、TOTALOPERATEREVETZ、PARENTNETPROFITTZ、ROEJQ、XSMLL、XSMLL_TB、ZCFZL、MGJYXJJE、EPSJB、BPS、ROIC | 2026-09-30 / 2026-06-30 |
| 日 K | `push2his.eastmoney.com/api/qt/stock/kline/get` | 日期、收盘、成交量、成交额；前复权 `fqt=1` | 截至 2026-10-26 |

### 为什么不是扶摇/iFinD？

- 扶摇/iFinD 文档页可访问，但接口需要 API Key；本次构建没有可用凭据。
- 题目写的是“金融数据优先使用”，同时说明“能力以实际可调用工具为准”。在没有 Key 的情况下，为了 24 小时内交付可验证主链路，使用公开接口完成真实数据快照。
- 数据获取已隔离在 `scripts/fetch_snapshot.py` 的 `fetch_quotes`、`fetch_financials`、`fetch_kline` 三个函数中；替换成扶摇/iFinD 时，只要输出同样的 `stocks` 字段契约，前端和引擎无需改动。
- 这是明确的取舍，不在页面或 README 中伪装成“已接入扶摇/iFinD”。

## 3. 字段口径与公式

| 字段 | 单位 | 公式 / 口径 | 缺失/异常处理 |
|---|---|---|---|
| `pe_ttm` | 倍 | 行情 f115 PE(TTM)，缺失时回退 f9 动态 PE；只取 >0 | 负值/缺失置空，标 `NEGATIVE_PE` / `MISSING_PE`；前端对 >1000 标 `PE_EXTREME` |
| `pb` | 倍 | 行情 f23 | 负值/缺失置空，标 `NEGATIVE_PB` / `MISSING_PB` |
| `market_cap` | 亿元 | f20 总市值（元）/ 1e8 | 缺失置空 |
| `pe_industry_pct` | % | 同行业内正 PE 由低到高的分位：`count(<=v)/n*100`；行业有效样本 ≥8 才计算 | 样本不足/PE 为空置空，标 `INDUSTRY_SMALL` |
| `pb_industry_pct` | % | 同上，PB 口径 | 同上 |
| `market_cap_industry_pct` | % | 同行业内市值由小到大的分位 | 样本不足置空 |
| `roe` | % | F10 `ROEJQ`，最新报告期加权 ROE，**未年化** | 缺失标 `MISSING_FIN` |
| `rev_growth` | % | F10 `TOTALOPERATEREVETZ`，最新报告期营业总收入同比 | 缺失置空；|值|>300% 标 `GROWTH_OUTLIER` |
| `profit_growth` | % | F10 `PARENTNETPROFITTZ`，最新报告期归母净利润同比 | 同上 |
| `gross_margin` | % | F10 `XSMLL`；银行/保险/证券通常为空 | 空值不当作 0；金融行业不适用 |
| `gross_margin_chg` | % | F10 `XSMLL_TB`，毛利率同比**相对变化**，不是百分点 | 空值不参与默认预设 |
| `debt_ratio` | % | F10 `ZCFZL` 资产负债率 | 银行/保险/证券天然高负债，不可与制造业直接比 |
| `ocf_ps` | 元 | F10 `MGJYXJJE` 每股经营现金流 | 缺失置空 |
| `ret_20d` / `ret_60d` | % | 日 K 收盘价：`close[-1]/close[-21]-1` / `close[-1]/close[-61]-1` | 历史不足置空，标 `NEW_LISTING_OR_SHORT_HISTORY` |
| `vol_60d` | % | 近 60 个交易日对数收益标准差 × √252 × 100 | 有效收益 <20 个置空 |
| `max_dd_60d` | % | 近 60 个交易日峰值到谷值的最大跌幅，负值 | 历史不足置空 |
| `above_ma60` | 是/否 | 最新收盘 > MA60 | 历史不足置空 |
| `ma20_gt_ma60` | 是/否 | MA20 > MA60 | 同上 |
| `report_date` | 日期 | 最新报告期；股票优先取 2026-09-30，否则 2026-06-30 | 早于 2026-06-30 标 `STALE_FIN` |
| `notice_date` | 日期 | 最新报告期披露日 | 缺失置空 |
| `quality_flags` | 数组 | 质量标记，见下表 | 不静默“正常” |

### 质量标记

`NEGATIVE_PE`、`MISSING_PE`、`NEGATIVE_PB`、`MISSING_PB`、`MISSING_FIN`、`STALE_FIN`、`FUTURE_REPORT`、`NEGATIVE_EQUITY`、`GROWTH_OUTLIER`、`MISSING_KLINE`、`NEW_LISTING_OR_SHORT_HISTORY`、`KLINE_STALE`、`LONG_SUSPENSION`、`SUSPENDED_OR_NO_PRICE`、`NO_VOLUME`、`ST`、`INDUSTRY_SMALL`。

## 5. 构建与复现

```bash
# 全量（约 2–3 分钟；行情 56 页 + 财报 30 页 + 5,215 条日K）
python scripts/fetch_snapshot.py

# 联调：只取前 30 只，跳过日K
python scripts/fetch_snapshot.py --limit 30 --skip-kline

# 校验 + 生成报告
python scripts/validate_snapshot.py --offline
```

脚本中 `2026-09-30` / `2026-06-30` 报告期与 `MIN_FRESH_REPORT_DATE` 是为了本次面试快照写死的；换日期时改这三个常量即可。日 K 抓取用 10 个并发，遇到限流会重试；如果大面积失败，脚本会保留旧快照（本次 18:xx 刷新遇到限流，就保留了 10:12 的完整版本，没有用缺失数据覆盖）。

## 6. 已知问题与处理

1. **盘中快照**：价格/估值是 10:12 的，收盘后会变；页面已标注，不伪装成收盘/实时。
2. **财报期混合**：1,002 只用三季报，4,213 只用中报；详情逐股显示报告期，跨股票对比会提示“报告期不同不可直接横比”。
3. **ROE 未年化**：中报 ROE 不能和年报 ROE 直接比；同报告期内横比相对公平。
4. **金融行业口径**：银行/保险/证券的负债率、毛利率不可与制造业直接比；毛利率为空时条件判为 missing。
5. **负 PE**：1,185 只，全部置空；估值条件不会把亏损股当便宜。
6. **极端值**：591 只增速 |同比|>300%，标 `GROWTH_OUTLIER`；PE >1000 在前端标 `PE_EXTREME`。
7. **行业分位**：55 只所属行业有效样本 <8，分位置空；条件会判 missing，不硬编。
8. **数据源不是扶摇/iFinD**：见第 2 节；这是本版本最大的已知取舍。
9. **无审计级复核**：公开接口 + 工程校验，不等同于金融数据终稿；不构成投资建议。
