01 / 问题定义

先把“AI 能做什么”拆成“谁在什么时刻卡住了”。

我没有把问题定义成“做一个 OCR 或报销机器人”，而是从审核员的一笔预审任务出发，拆开读、找、核、问四类重复工作。

01

读

从发票、行程单、支付截图里重复读取金额、日期、商户和票号。

02

找

定位费用类型对应的制度、额度和必需附件。

03

核

对照字段一致性、额度、日期窗口和材料完整性。

04

问

发现问题后重新组织原因，联系员工补充或修改。

产品切入审批前预审

既能创造效率价值，又不越过正式审批、付款和财务责任边界。

02 / 方案与责任边界

不是让模型替人审批，而是让每一层只承担自己擅长的责任。

这是本项目最重要的 AI 产品判断：生成式能力负责理解和表达，确定性规则负责制度判断，人工负责事实确认与最终预审决定。

AI 层

读取与解释

抽取金额、日期、商户等字段；绑定页码/区域证据；生成受约束的异常说明。

不能直接输出“合规”结论
规则层

执行制度

使用发布中的规则版本，将已确认输入计算为 PASS、EXCEPTION 或 UNKNOWN。

未知不会被默认通过
人工层

确认与决定

修正事实、处理冲突和未知，选择预审通过、退回或要求补充，并留下理由。

人工决定不等于正式付款审批

04 / 从 Demo 到真实验证

90 天路线图的终点不是“接上 ERP”，而是知道值不值得继续投入。

用 Gate A–D 管理不确定性：问题和购买者 → 任务和规则 → 受控真实数据 → 付费与扩大。任一 P0 安全问题都可以冻结路线图。

GATE A

问题与购买者

证明重复核对真实存在，并找到拥有预算、愿意提供下一步承诺的人。

退出：≥3 位负责人愿意进入材料评估
GATE B

任务与规则

证明审核员能理解三态结果、异常证据和人工责任边界。

退出：漏报 0、责任边界误读 0
GATE C

受控真实数据

在授权、最小化、专业复核的前提下完成连续窄场景预审。

退出：连续 2 周产生 WVP
GATE D

付费与扩大

确认持续使用的价值能够覆盖处理、支持、获客和合规成本。

退出：付费下一步 + 单案贡献毛利为正

06 / 产品反思

这个项目最值得展示的，是我知道哪些答案还没有被证明。

最强点

把 AI、规则和人工的责任边界写成了可运行状态

低置信、UNKNOWN、EXCEPTION、字段修正和人工决定不再只是口号，而是能在原型中演示、在数据契约中回放、在指标中监控。

最大不足

还没有真实审核员、真实制度和真实成本证据

当前用户洞察、商业模式和模型质量都属于验证前假设；30 条合成案例适合测试结构，不足以代表真实世界。

重做优先级

先做 Gate A 的真实任务观察，再决定扩大哪条能力

如果问题频率、规则稳定性或付费者不成立，我会缩小到资料完整性或规则解释，而不是继续堆叠系统集成功能。
